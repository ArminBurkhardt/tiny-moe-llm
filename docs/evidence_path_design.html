Embeddings choose. Cross-attention reads. The trunk reasons.

A 384-d embedding search picks candidate chunks because it is cheap. A cross-attention reader then attends over the tokens of those chunks, so exact wording reaches the model. World facts live in the store. The trunk keeps language, common sense and reasoning.

1 · pipeline

Two streams, three hand-offs

Your split is the right one and the proposal keeps it. The additions are a clean way for the selector to steer the reader, and a training recipe that stops rewarding recall from weights.

Store

  • Fixed windows of 128 model tokens, sentence aligned.
  • MinHash deduplicated, one global chunk id, provenance kept.
  • Key: bge-small-en-v1.5, 384-d, unit norm, fp16.
  • No cached encoder states. At 1.5 KB per token a 0.4B-token store would be 600 GB. Chunks are encoded on the fly.
  • Target size: at least 0.4B tokens, about one store token per model parameter.

Selector

  • q = normalize(down_proj(norm(h)) + loop_query_bias[loop])
  • Keys stay raw bge. The trained key_adapter goes, so the index is never rebuilt.
  • Softmax over the k candidates plus one learned null key. Null mass means nothing relevant.
  • Always on. The router never specialized, so relevance must not depend on it.
  • No value read. It carries gist only.

Reader

  • Cross-attention, 16 query heads x 48, 4 KV heads.
  • Reads encoded chunk tokens, so spans can be copied.
  • Selector prior enters the attention logit per token. It is causal by construction.
  • One learned sink slot per segment with a zero value, so the reader can attend nowhere.
  • K and V are loop invariant, so one cache per buffer serves all loops.
2 · reader math

How the selector steers the reader

The repo's current coupling is 1 + evidence_gate_scale * sigmoid(chunk_mean_mass). It averages over the whole document, so it leaks future tokens in training, and its input range makes it nearly constant. The replacement adds the selector's own logit to the attention logit through a one-hot channel. It needs no attention bias argument, so flash-attn varlen still works.

# M = max chunks per segment (static). head_dim grows from 48 to 48 + M, rounded to a multiple of 8
k'[j] = [ W_k e[j] ; onehot(rank(chunk(j))) ]        # evidence token j, v padded with zeros
q'[t] = [ W_q x[t] ; sqrt(48) * b[t, 1..M] ]         # query token t
logit(t, j) = q'[t] · k'[j] / sqrt(48)
            = content(t, j) + b[t, chunk(j)]          # softmax_scale = 48^-0.5 passed explicitly

b[t, c] = gamma[h] * z[t, c]  -  lambda * log(n_c)  +  vis[t, c]
z[t, c] = cos(q_sel[t], key[c]) / tau                # the selector's own logit, already [T, M]
vis     = 0 where chunk c is visible to token t, else -1e4
sink    = one extra slot per segment: learned key, value 0

Why this form

  • The selection loss and the reader use the same number z. Ranking learned from gold flags transfers directly.
  • gamma is one scalar per head. At zero its gradient is sum(g * z), which is nonzero, so there is no dead chain.
  • lambda * log(n_c) removes the length bias. A chunk three times longer otherwise gets 1.1 nats for free.
  • The visibility mask also expresses the per-window staircase of the from-scratch run.

Init and cost

  • POC: gamma = 0, lambda = 0. The reader is unchanged at step 0.
  • From scratch: gamma = 1, lambda = 0.
  • M = 16 gives head_dim 64, about +33% on the reader's attention.
  • M = 40 covers 32 chunks plus the many condition and gives head_dim 88.
  • A read site is about 7 MFLOP per token, 1.4% of the body. This is an estimate.
My first draft added P * key to the reader's keys and Q * q_sel to its queries. The Opus review showed that this mostly learns content-by-selector cross terms, and that the pure selector term is a new bilinear form unrelated to the cosine the selection loss trains. The one-hot channel replaces it.
3 · forward pass

One loop of the block

0
Input. step_input = h, shape [B, S, 768]. cu_seqlens is built in-thread from document_ids.
1
Selector. Scores the visible candidate keys for every token. Produces z [T, M] and the null mass. Runs first so this loop's scores steer this loop's read.
2
Reader. read = CrossAttn(x = step_input + evidence_query_bias[loop], K/V = encoded chunks, prior = b). Skipped entirely when no evidence is attached, which keeps that path bit-identical.
3
Always-on experts. acc = shared_mlp(h) + shared_attn(h).
4
Routed experts. Self-attention and cross-attention experts run densely. 32 MLP experts run sparse at top-k 2 through one grouped GEMM. The router is loop conditioned by loop_router_bias.
5
Block update. h = h + loop_scale[loop] * dropout(post_norm(acc)).
6
Evidence update. h = h + g_loop[loop] * RMSNorm(o_proj(read)). The read enters after post_norm, so it keeps its own share of the residual. CHANGE
7
Readout. The normed state of every loop goes to the chunked CE. The groundedness head reads read and the null mass at the last prompt token of each answer span.
Neutrality moves from o_proj to g_loop. A norm placed after a zero-init o_proj has a gradient near 1/sqrt(eps) at zero, so one optimizer step would put a unit-RMS read into the residual. With g_loop = 0 and a default-init o_proj, the first step is still exactly neutral and g_loop gets a real gradient. From scratch g_loop starts at 1.

Training step

1
Batch. input_ids, document_ids, labels, evidence ids, chunk_keys [B, C, 384], slot map, chunk_gold, condition_ids, answerable flag. Nothing ragged leaves the dataloader.
2
Encode evidence once. evidence_from_batch runs the dense decoder over the chunks, chunk-causal, positions restarting per chunk. Cached for all loops.
3
Forward. Dense decoder, then the block at the sampled depth. Returns per-loop normed states, not logits.
4
Loss. Chunked CE through main_lm_head, plus the four auxiliary terms.
5
Optimizer. On every eighth micro step: copy gradients to the fp32 masters, clip at 1.0, AdamW on the masters, write back to bf16, clear the gradients by hand.
6
Log every 10 steps. |shared_evidence.o_proj|rms, external mass per condition, selection:, grounded:.
7
Eval every 2.5M tokens, and at step 0. Fixed-target answer CE under gold and under none, on held-out rows.

Two candidate shapes. M keeps today's width and FLOPs. Experts stay at 8 per sublayer in both shapes, so the parameters that can hold facts are about 130M in M and 225M in L, against 170M today. If closed-book recall rises in the pilot, cut experts before cutting width. The 5k-hour ceiling in the plan leaves room for L; the data cap is 400B tokens.

Building one training sequence

1
Window. Split the 4096 tokens into 16 windows of 256.
2
Query. bge embedding of the preceding window's text. Offline, cheap.
3
Retrieve. Top 2 chunks per window. Exclude the document itself.
4
Filter near duplicates. Drop a candidate whose longest common token run with the target is 32 or more, or whose 8-gram Jaccard is 0.3 or more. Mirrors otherwise turn the reader into a copy machine.
5
Tag fact spans. Entities, numbers, dates. A span is supported when it occurs in a visible chunk. Numbers need two tokens or a matching context n-gram.
6
Flag gold. A chunk holding a supported span is gold for the selection loss and the contrastive loss.
7
Rewrite. Apply the counterfactual swap and the tail anonymization below.
8
Report. Share of supervised tokens whose facts are in the buffer. Under about 20% is a failed build.

Token tables and the head

Today: four unrelated views of the token

  • Input embedding 50.3M, per-layer embeddings 16.8M, router embedding 2.1M, two factored heads 16.5M. Together 85.7M, about a quarter of the model.
  • The main head is a 768 x 768 projection followed by four independent 192 to 16384 blocks, split by token id. Each vocab quarter lives in its own 192-d subspace.
  • This is the one parameter saving in the model that constrains the output distribution itself, and it was never measured.

Next run: one table, tied

  • The head becomes norm(h) @ A @ E^T with E the input embedding and A a 768 x 768 adapter. New parameters: 0.59M, plus 0.29M for the MTP adapter.
  • The cost moves to compute: a full 65536-wide softmax is about 101 MFLOP per token per application against 26 today. A fused linear plus cross-entropy kernel and a subsampled MTP head roughly cover it.
  • Init E at std 1/sqrt(768), or the tied readout saturates at step 0. Exclude the tied table from weight decay on the output side.
  • Gate: the plan's oracle-head measurement. Tie if the factoring costs 0.02 nats or more. Below that, keep the factored head and still collapse the other tables.

9 · internal reasoning

Making the loop reason over what it reads

There is good reason to expect the loop to compose facts it reads. There is no clean measurement yet that it does. Every per-loop number on record comes from a checkpoint whose third loop passed only 8% of its update for all 16B pretraining tokens.

Synthetic chains, 10% of tokens

  • Fictional entities, so weights cannot know the answer.
  • Hops 1 / 2 / 3 at 25 / 50 / 25 by rows, chunk order shuffled.
  • 6 to 14 distractors: same relation with other entities, bridge relation with other entities, and one full decoy chain.
  • Held out: 4-hop chains and unseen hop-2 templates.
  • A hop index per gold chunk is written for evaluation only.

Validity rule

  • Score accuracy by hops and by loops run.
  • Every cell with fewer loops than hops must sit at chance.
  • Anything above chance there is a leak in the data, because the read structure makes it impossible.
  • A 1-hop curve must saturate before any null result is read.

Strong evidence

The read structure forces depth for composition. Small looped models compose on synthetic tasks, including at 124M parameters and below.

Weak evidence

Transfer to natural multi-hop questions at this size. Published second hops fail off template, and this model reads BoolQ below chance.

No evidence

Any loop measurement here without the halt gate confound. Any looped model with an evidence port showing a depth curve on real questions.

With 3 passes the model can compose about 2 to 3 hops over evidence before readout. The schedule to 5 trains the block to keep working from its own output; inference stays at 3 passes, 4 at most. At 3 sublayers per pass that is 17 to 20 layer-equivalents per token against 11 today, and 26 at the training ceiling. Whether 2 or 3 sublayers per pass is right is a pilot arm at matched compute.

  • Offline preparation at 100B tokens: tagging is about 15 H100 hours, bge queries about a third of that.

13 · open risks

What can still fail

Facts leak in through the input

Without the counterfactual swaps A1 is expected to fail. The swap rate and the anonymization rate are first guesses and need a sweep in the pilot.

Small models ignore evidence

Models of 7B and under have been measured ignoring oracle passages most of the time. At about 120M the pilot may come out flat. The matched control and A6 decide.

Retrieval mismatch and leakage

The reader trains on bge's errors and serves on its own. Near-duplicate continuations inflate the language-model gain. Report gains by overlap tier.

Reader bandwidth

One read per loop is narrow next to designs that read in every layer. The dense-layer reads are the prepared answer, not a measured one.

Coverage

With the document itself excluded, a fact that appears in one document only is never supported. It is masked, never memorized and never practised.

Multi-hop stays implicit

The buffer is fixed per forward. Re-querying between loops and appending chunks is untrained and deferred until the pilot passes.
