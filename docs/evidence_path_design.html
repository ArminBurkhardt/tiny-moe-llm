Embeddings choose. Self-attention reads. The trunk reasons.

A 384-d embedding search picks candidate chunks because it is cheap. The tokens of those chunks then enter the looped block's shared self-attention as leading keys and values, so exact wording reaches the model through the circuit that already copies from a prompt. World facts live in the store, reached through the retrieval pathway; reasoning happens in written tokens, with the looped trunk as computation per token (the goal as reworded 2026-10-25; the original goal, reasoning in the looped trunk, is kept beside it as the aspiration to revisit after the real run). The trunk keeps language, common sense and reasoning skill.

1 · pipeline

Two streams, three hand-offs

The split between choosing by embedding and reading token states stays. Since 2026-10-03 the read is no longer a separate cross-attention module: the chunk tokens are leading keys and values of the shared self-attention. The other additions are a clean way for the selector to steer the read, and a training recipe that stops rewarding recall from weights.

Store

  • Fixed windows of 128 model tokens, sentence aligned.
  • MinHash deduplicated, one global chunk id, provenance kept.
  • Key: bge-small-en-v1.5, 384-d, unit norm, fp16.
  • No cached encoder states. At 1.5 KB per token a 0.4B-token store would be 600 GB. Chunks are encoded on the fly.
  • Target size: at least 0.4B tokens, about one store token per model parameter.

Selector

  • q = normalize(down_proj(norm(h)) + loop_query_bias[loop])
  • Keys stay raw bge. The trained key_adapter goes, so the index is never rebuilt.
  • Softmax over the k candidates plus one learned null key. Null mass means nothing relevant.
  • Always on. The router never specialized, so relevance must not depend on it.
  • No value read. It carries gist only.

Reader

  • No module of its own. The encoded chunk tokens become leading keys and values of the shared self-attention in every loop, under one softmax with the segment's own causal keys.
  • They pass through that attention's own norm, k_proj and v_proj, so spans are copied by the circuit that copies from a prompt.
  • Prefix rotation: the evidence keys sit at the positions the text right before the segment would hold.
  • Selector prior enters the attention logit per token, on the evidence keys only. It is causal by construction.
  • One learned sink slot per segment with a zero value.
  • Measured at 35M parameters and 100M tokens: gold card top-1 0.92, where the cross-attention reader reads 0.01.
2 · reader math

How the selector steers the reader

The repo's current coupling is 1 + evidence_gate_scale * sigmoid(chunk_mean_mass). It averages over the whole document, so it leaks future tokens in training, and its input range makes it nearly constant. The replacement adds the selector's own logit to the attention logit through a one-hot channel. It needs no attention bias argument, so flash-attn varlen still works. With the key/value read the channel is a head-dim extension of the shared self-attention: the one-hot sits on the evidence keys and the segment's own keys carry zeros. The key/value read is built and measured; the channel and the sink are not built yet.

# one softmax per query token over [ evidence prefix of its segment ; the segment's own causal keys ]
# d = head dim (48 today, 64 at shape L). M = max chunks per segment (static). head_dim grows to d + M, a multiple of 8
k'[j] = [ W_k norm(e[j]) ; onehot(rank(chunk(j))) ]  # evidence token j, v padded with zeros
k'[i] = [ W_k norm(x[i]) ; 0 ]                       # the segment's own token i, causal
q'[t] = [ W_q norm(x[t]) ; sqrt(d) * b[t, 1..M] ]    # query token t
logit(t, j) = content(t, j) + b[t, chunk(j)]         # softmax_scale = d^-0.5 passed explicitly
logit(t, i) = content(t, i)                          # own keys see no prior

pos(j)  = start_s - E_s + j                          # prefix rotation on the content dims: the E_s evidence tokens of segment s
                                                     # sit where the text right before the segment would; negative positions allowed
b[t, c] = gamma[h] * z[t, c]  -  lambda * log(n_c)  +  vis[t, c]
z[t, c] = cos(q_sel[t], key[c]) / tau                # the selector's own logit, already [T, M]
vis     = 0 where chunk c is visible to token t, else -1e4
sink    = one extra slot per segment: learned key, value 0

Why this form

  • The selection loss and the reader use the same number z. Ranking learned from gold flags transfers directly.
  • gamma is one scalar per head. At zero its gradient is sum(g * z), which is nonzero, so there is no dead chain.
  • lambda * log(n_c) removes the length bias. A chunk three times longer otherwise gets 1.1 nats for free.
  • The visibility mask also expresses the per-window staircase of the from-scratch run.

Init and cost

  • The graft's arm C (the channel at gamma = 0) never ran: arms A and B were killed at 10M.
  • From scratch: gamma = 1, lambda = 0.
  • At d = 48, M = 16 gives head_dim 64 and M = 40 gives 88; at shape L (d = 64) they give 80 and 104. The extension now widens the shared self-attention itself, on its own keys as well.
  • M = 40 covers 16 windows at top 2 (32 chunks) with room to spare. The pilot's QA buffer is capped at 8 chunks and has no many condition.
  • The earlier estimate of 7 MFLOP per read site was for a separate cross-attention. The key/value read instead lengthens the key axis of an attention that already runs; its cost is not re-derived.
Why the read moved into the self-attention (2026-10-03). At matched 100M tokens the cross-attention reader ranked the gold card's value at 0.47 at tier 1 and followed a swapped card 2% of the time, although the same model copied a card from its prompt at 0.10 to 0.13. A separate module has to relearn copying; evidence presented as leading keys of the model's own attention inherits it. Training that read also trained in-context copying (prompt read 0.003), and filler validation CE is unchanged (4.481 against 4.509).
The first draft added P * key to the reader's keys and Q * q_sel to its queries. The Opus review showed that this mostly learns content-by-selector cross terms, and that the pure selector term is a new bilinear form unrelated to the cosine the selection loss trains. The one-hot channel replaces it.
3 · forward pass

One loop of the block

0
Input. step_input = h, shape [B, S, 768]. cu_seqlens is built in-thread from document_ids.
1
Selector. Scores the visible candidate keys for every token. Produces z [T, M] and the null mass. Runs first so this loop's scores steer this loop's read.
2
Evidence keys. The encoded chunk states go through shared_attn's own norm, k_proj and v_proj, are rotated at their prefix positions, and the values are scaled by evidence_loop_scale[loop]. Skipped entirely when no evidence is attached, which keeps that path bit-identical.
3
Always-on experts, with the read. acc = shared_mlp(h) + shared_attn(h, prefix = evidence K/V, prior = b). One softmax per token over the evidence prefix and the segment's own causal keys, one flash call. There is no reader query bias.
4
Routed experts. Self-attention and cross-attention experts run densely. 32 MLP experts run sparse at top-k 2 through one grouped GEMM. The router is loop conditioned by loop_router_bias.
5
Block update. h = h + loop_scale[loop] * dropout(post_norm(acc)).
6
No separate evidence update. The read lands through shared_attn's own o_proj inside step 3. The earlier g_loop[loop] * RMSNorm(o_proj(read)) add after post_norm went with the cross-attention module. DROP
7
Readout. The normed state of every loop goes to the chunked CE. The groundedness head reads the output of the reading attention and the null mass at the last prompt token of each answer span.
Neutrality with evidence attached is given up. The read shares the softmax with the segment's own keys, so attaching evidence changes the forward from the first step. From-scratch training does not need a neutral start; the zero-init gain existed for grafts, and the graft branch is closed. With no evidence attached the forward is still bit-identical to the model without the port. The cross-attention reader stays loadable as the legacy mode.

Today: four unrelated views of the token

9 · internal reasoning

Making the loop reason over what it reads

There is good reason to expect the loop to compose facts it reads. There is no clean measurement yet that it does. Every per-loop number on the 16B lineage comes from a checkpoint whose third loop passed only 8% of its update for all pretraining tokens. The micro arms are from scratch and free of that gate, and they now hold one closed-book depth curve (arm (a), 2026-10-04: a weakly stored fact is recalled better after a second pass) and one per-exit read on filler (2026-10-05: the second pass is worth 0.094 nats per token, spread evenly over tokens, the third 0.006), but none over evidence.

Proposed objective and depth schedule

L = CE(head(coda(h_D)))                              # one loss, on the last loop run, through the coda
  + 0.10 * MTP(coda(h_D)) * span_weight                # balancing loss-free, no aux term (2026-10-21)
  + 0.10 * L_sel + 0.10 * groundedness                 # the 0.10 contrastive term left the spec 2026-10-21

p[k,c] = selector mass of loop k on chunk c, renormalized over visible chunks
u[c]   = 1 - product over loops k in the gradient window of (1 - p[k,c])
L_sel  = mean over (selector, token) of mean over visible c of BCE(u[c], gold[c])

depth D     : 3 with p 0.7, 4 with p 0.2, 5 with p 0.1   (expected 3.4; inference 3, at most 4)

Synthetic chains, 10% of tokens

  • Fictional entities, so weights cannot know the answer.
  • Hops 1 / 2 / 3 at 25 / 50 / 25 by rows, chunk order shuffled.
  • 6 to 14 distractors: same relation with other entities, bridge relation with other entities, and one full decoy chain.
  • Held out: 4-hop chains and unseen hop-2 templates.
  • A hop index per gold chunk is written for evaluation only.

Validity rule

  • Hops are bounded by sequential read sites before readout, not by loops: 2 per pass in the pilot design.
  • Score accuracy by hops and by read sites at fixed D = 3, zeroing the reader output at every site after site j (read ablation). Truncating depth is not used: the minimum depth is 3, so 1- and 2-loop exits are untrained and would sit at chance from readout failure.
  • Every cell with fewer read sites than hops must sit at chance, 1 / (type-matched candidate answers in the buffer). Anything above chance there is a leak in the data.
  • The L1 control is the read-ablated model or the per-loop-CE arm, never the no-retrieval arm, which cannot see the chains.
  • Falsifier of the loop clause: read sites past the first pass add under 5 points on held-out 2-hop at D = 3.
  • A 1-hop curve must saturate before any null result is read.

Strong evidence

The read structure bounds hops by sequential read sites before readout. Small looped models compose on synthetic tasks, including at 124M parameters and below.

Weak evidence

Transfer to natural multi-hop questions at this size. Published second hops fail off template, and this model reads BoolQ below chance.

No evidence

Any looped model with an evidence port showing a depth curve on real questions. Without the halt gate confound there is one reading: in micro arm (a), from scratch with per-loop CE, loop_scale settled at 1.61 / 0.63 / 0.21 and loop 3 reads about 0.05 nats under loop 2 by 275M tokens.

13 · open risks

What can still fail

Facts leak in through the input

Without the counterfactual swaps A1 is expected to fail. The swap rate and the anonymization rate are first guesses. Arm (b), the input-side leak test, ran on 2026-10-04 and stored nothing at 3 sigma, so the arm (c) leak is most likely on its supervised spans, which anonymization as built barely reaches. The copy-first warm-up arm narrowed it on 2026-10-05: with no consistent real-value target the input side and the card path store nothing detectable, so the store is written by supervised real-value spans, before and after the reader copies (tier 1000 was stored again after copying). A swap rate 0.30 branch (2026-10-06) and a placeholder name arm (2026-10-08) both left that tier 1000 level where it was, so it is not set by the swap rate or by the count of supervised spans that pair the real name with the real value.

Arm (c) leaks

At 300M arm (c) is 3 sigma off its prior at tier 100 on both forms, although its read copies completely in distribution. The leak is there at 50M, before copying, and does not grow after 100M. The copy-first warm-up arm stored nothing until real values were supervised and then stored tier 1000 facts again with copying in place, so copying first alone does not stop storage of frequent facts. At 300M it brings tier 100 inside 3 sigma on both forms and sits under the original arm in every cell, short of 3 sigma per form, while tier 1000 still leaks (0.085, z 6.4). The leak is recorded as known (decided 2026-10-05); a swap rate 0.30 branch from its 100M save left it where it was (0.083), and so did a placeholder name in half of the gold-present documents (0.099, paired +0.011 at z +1.8 pooled, read 2026-10-08), which halves the supervision pairing the real name with the real value: the level does not follow that dose, so the span weight by a copy criterion is dropped and no lever against it is left on the list. What writes it is open (the documents without the gold card that carry the real name, the input path, the prior drifting). The review of 2026-10-24 named two candidates, both built that day as builder flags with their splits and read on 2026-10-25 as copy-first warm-up arms: value-first templates ("{v} is the hometown of {s}.") that supervise the name from the value when they open a biography, a direction the closed-book read cannot see (--mask-first-name-mention, arm m1), and gold-absent documents that count a value as supported when it collides with a distractor card, about 0.56% of all spans (--support-gold-only, arm g1). Both are falsified (tier 1000 paired z 0.7 and 0.1 in distribution, 1.3 and 0.9 held out, against a bar of 3), so what writes the level stays open; support from the gold card only raised held-out following of a swapped card from about 0.67 to 0.79 at no cost; the same-code twin cfb (the flagless splits on today's code, read 2026-10-25 evening) confirms both falsified (every paired cell within z 1.1); copying at the switch is 0.95 to 0.96 on cfb against 0.88 to 0.90 on m1 and g1, so the slower copying was the flags; filler CE 3.8885 against the recorded arm's 3.9106, so the 0.022 gap is the code since 2026-10-05, not the flags (the cosine's planned steps, about 11,907 and 11,911, rule the estimator out); tier 100 reads z 2.9 in distribution and 3.7 held out by form, over 3 sigma held out on all three arms, accepted as the recipe's known state on one seed (RUN2.md row 9, no second seed). The goldfish loss is expected to do no better than a dose cut on paraphrased renders. The pilot keeps swap rate 0.15 with this leak known; RL, planned later and parked today, would act on behaviour at conflicts, not on what is stored.

Small models ignore evidence

Models of 7B and under have been measured ignoring oracle passages most of the time. At 35M the key/value read follows a swapped card on every in-distribution item by 300M (0.61 to 0.64 on a held-out template), but on fictional cards. On natural text the pilot may still come out flat. The matched control and A6 decide.

Retrieval mismatch and leakage

The reader trains on bge's errors and serves on its own. Near-duplicate continuations inflate the language-model gain. Report gains by overlap tier.

Reader bandwidth

One read per loop in the POC, two per pass in the pilot design, is narrow next to designs that read in every layer. The dense-layer reads are the prepared answer, not a measured one.

Coverage

With the document itself excluded, a fact that appears in one document only is never supported. It is masked, never memorized and never practised.

RL pays for recall from the weights

A reward on a correct answer given without its evidence trains closed-book recall, which is the leak with a reward behind it. Post-training pays answers only with the supporting chunk visible, pays abstention without it, and reads A1 after every stage. Rollouts are its cost: decode with evidence has no KV cache today.

Multi-hop stays implicit

The buffer is fixed per forward. Re-querying between loops and appending chunks is untrained and deferred until the pilot passes.

The loop does not compose

L1 is falsified at pilot shape: lookup reached 0.99 and every composition cell stayed at chance through one more epoch of chains. Written as a bridge, the same chains compose at one read site (R9, 0.997 held out at the final, 0.982 at 10M): the model composes as soon as the intermediate entity is a token it writes and reads back. 6f reasons in written tokens, the loop as computation per token; whether the loop composes at the real run's size stays open, and the written depth does not extend past the trained one. Trained on chains alone, the bridge checkpoint lost every other gate (R5, 2026-10-25), so 6f mixes the pretraining slices back in.

The pilot corpus has two flaws

Arm C alone trained on 50.11M tokens of 4094-token QA rows and reached its cosine floor where the evidence arms stopped early, and about 7.4% of the validation slice is supervised text both arms train on (6.7% more in arm C's rows only). The held-out CE comparisons and A6 carry these caveats; the rank reads that decide A1 do not. Decided 2026-10-24: the reader keeps dropping those rows, so later arms on these merges stay matched to arm P; a clean validation slice (0.99% verbatim overlap with the QA training rows against 13.3%) was built for a CE re-read of the three finals. Read 2026-10-25: on clean text the control's lead over arm P at exit 3 shrinks from 0.025 to 0.002, so its lower held-out CE was this contamination, not better language; E4 sits 0.007 behind P.

A faster optimizer stores more

Muon passed on loss and copying at micro but stored the biographies about twice as early and leaked more by the sign at every tier above 1 in distribution. It is out of the real-run spec; any later optimizer change is read on the leak, not the loss.
