# Direction review against the retrieval-only goal (2026-09-29)

Scope: the repo as of `aea3372`, before the first `--evidence` finetune. Read against one goal:

> All information the model uses is supplied through retrieval; the LLM's only job is reasoning
> with that information.

Method: seven read-only audits (IR expert, evidence port, training flow, corpus, evals, plan, test
health), five literature sweeps restricted to work the repo docs do not cite yet, one adversarial
verifier per audit, one citation checker per sweep, three independent judges. 27 Sonnet agents, no
training launched, no checkpoint evaluated, no file changed. Findings marked **confirmed** were
re-read by a second agent or by the main agent; **partial** means the mechanism is real and the
consequence is an inference; **unverified** means one reader only. Paper claims were checked
against the arXiv abstract page only, so numbers that live in a paper's body are flagged.

Health: 14 of 14 test scripts pass (11 GPU-free, 3 evidence tests on the idle GPU). CLAUDE.md,
NEXT.md, `config.yaml` and the disk agree on the Phase 4 state.

## 1. Verdict

| question | answer |
|---|---|
| Is the direction sound? | Yes for the weak form: external evidence, read through a side channel, selected by the IR expert, pretrained with retrieval from token 0. The literature of 2025-2026 moved the same way. |
| Is the goal achieved? | No. Nothing has trained, and nothing in the repo can measure it. |
| Is the strong form achievable? | Not as worded. No published system has a fact-free trunk that reasons well. The reachable target is "no long-tail or episodic facts in weights, a common-sense and language core stays". |
| Is it achievable with the current architecture? | The port can plausibly deliver span lookup. Reasoning over evidence through one cross-attention read per loop is unproven, and the pending run is the first measurement of it. |
| Is it achievable with the current training flow? | No. The corpus and the real run recipe both keep rewarding facts produced from weights. |
| Should the pending run launch as is? | No. Its kill metric reads the wrong quantity and its validation split is inside the training set. Fix those first (section 3), then run it as a mechanism check only. |

## 2. The goal and the design do not say the same thing

**The IR expert is a selector, not the information channel.** Its external value is
`value_adapter(key)`, a linear map of one pooled 384-d bge vector
([information_retrieval.py](../modules/model/information_retrieval.py), `_memory_values`), and
that reaches the residual only through `g_proj -> up_proj -> direct_gate`, with `direct_gate`
zero at the seed. No span can be copied out of it. Token-level content flows only through
`shared_evidence`, the un-routed reader. xRAG (2405.13792) shows what a single retrieval vector
recovers: gist, not exact facts. So the IR expert should not be made to carry content.

**The model never retrieves.** The corpus builder chooses the 1 to 32 chunks; the IR expert
re-weights a buffer it was handed. The first stage is frozen bge-small. The buffer is fixed per
forward, so loop 2 can re-weight but cannot fetch.

**The plan commits to the weak form only** (confirmed). NEXT.md:106 states the thesis as
"retrieval supplies at eval time the knowledge peers had to store in weights". The decisions table
keeps a parametric memory option (NEXT.md:150) and a 20% replay floor (NEXT.md:143). R1's floor is
LMLM's 19% relative drop, which leaves about 40% of FactScore in the trunk. There is no
"closed-book factual accuracy near chance" bar anywhere.

Proposed wording, which the design can satisfy:

> All world facts come from an external store through the retrieval pathway: the IR selector
> chooses, the evidence reader carries. The trunk holds language, common sense and reasoning.

| information type | lives in | basis |
|---|---|---|
| entity, episodic, long-tail facts, numbers, dates | store | the goal |
| rare-word and domain definitions | store | Pouransari et al. (2510.02375) |
| syntax, common word meaning, coreference | trunk | same; BabyLM findings (2504.08165) |
| common sense and basic priors | trunk | nothing published removes these |
| procedural and reasoning skill | trunk | the goal |

## 3. Before the `--evidence` launch

Ordered by how badly each would mislead the run.

1. **The in-run kill metric compares different targets** (confirmed,
   [sft.py:670](../scripts/sft.py#L670)). The per-condition `[eval]` CE uses each row's own label:
   the answer under `gold`, a refusal phrase under `none`. NEXT.md:930 already measured that gap
   at -3.25 nats, wrong sign, on a seed whose reader is provably zero. The `none` bucket also
   holds replay rows. The 0.0000 baseline quoted in CLAUDE.md comes from
   `eval_abstention.py --evidence-port`, which forces the real answer under every condition. The
   kill rule has to read that fixed-target gap, either by adding the pass to `evaluate()` or by
   running the eval script on the first checkpoint.
2. **The QA validation split is inside the training set** (confirmed,
   [prepare_evidence_data.py:883](../scripts/prepare_evidence_data.py#L883)). The split is drawn
   per rendered row after the QA sources rewind, so the same question lands in both. The audit
   counted 7,440 of 7,440 QA val prompts present in train. The gold-vs-none gap and the held-out
   groundedness AUROC are therefore read on seen questions. Build the val set from SQuAD dev and
   HotpotQA dev, or split by source row id before the condition draw.
3. **The first eval lands exactly at the kill point** (partial). `eval_every_tokens` is 10M and
   there is no step-0 eval, so the decision has one reading and no trajectory. Warmup covers the
   first ~4.2M tokens. Set the cadence to ~2.5M and log an eval before step 1.
4. **The selector gate is not causal** (confirmed by the main agent,
   [evidence.py:148](../modules/model/evidence.py#L148),
   [moe.py:632](../modules/model/moe.py#L632)). `chunk_mean_mass` averages the selector's weight
   over every token of the document, and that one number gates the evidence states every position
   reads. The weight at position `t'` depends on the input token at `t'`, which is the label of
   `t' - 1`. So the read at position `t` carries information from tokens after `t` in training,
   and a KV-cached decode, an uncached decode and training each compute a different gate. It is
   inert while `evidence_gate_scale` is zero. Freeze the scale at zero for the first run, or make
   the mean cumulative.
5. **The same gate has almost no dynamic range** (confirmed by the main agent). Its input is a
   probability mass, so `sigmoid(mass)` sits between 0.50 and 0.73, and for a mass of a few
   percent between 0.50 and 0.51. Gold and distractor differ by about 1% of the scale. Use a
   z-scored log mass if the coupling is wanted.
6. **The reader's rotary phase is meaningless** (confirmed,
   [gemma4.py:94](../modules/model/gemma4.py#L94)). The query is rotated by its absolute position
   in the prompt, the key by its position inside the chunk. The offset between the two is
   unrelated to content and changes token to token. The encoder already gave the chunk tokens
   their positions. A position-free reader is a one-flag A/B and is the first arm to try if the
   gap stays small.
7. **The eval chunks SQuAD differently from training** (partial). Training writes one chunk per
   SQuAD passage; `--chunk-tokens` defaults to 128 and its help string says that matches the
   builder. It is deliberate as a selector test and should be a secondary row; the primary G3
   reading wants one chunk per passage.
8. **Small ones.** The selection loss mask is off by one position (unverified, low). Eval
   distractors can be drawn from the same SQuAD context (confirmed, about 2 rows per 2000).
   `is_fresh_loop_param` and the by-hand gradient clear in `train_step` have no test (confirmed),
   and they route exactly the tensors this run trains. Print `|g_proj|rms` of the seed once: if it
   is zero, `g_proj` and the zero-born `direct_gate` hold each other at zero.

Arithmetic that came out fine: at 10M tokens the port's LR is 2.99e-4 after ~238 optimizer steps,
enough for `o_proj` to reach an RMS of 0.02 to 0.05 if its gradient is sign-consistent. `o_proj`
gets a full-rank nonzero gradient at step 0, unlike `g_proj` in the scale-fix arm, and the
selection loss is a second path that does not depend on it. The stall that killed G2b is not
structurally repeated. What can happen instead: `o_proj` learns first from a random reader, so its
RMS rises while the gap stays at zero. RMS alone is not the signal.

## 4. What blocks the goal

### 4.1 The corpus trains parametric recall (confirmed)

By supervised tokens, measured on `evidence_train` (74.6M):

| source | share of supervised tokens | evidence carries the target's facts |
|---|---|---|
| web continuation, gold or mixed | 37.7% | partly: one 384-token span, continuation averages 685 tokens after it |
| web continuation, distractors or none | 16.6% | no, and the real continuation is still supervised |
| replay | 37.7% | no evidence at all |
| QA | 8.1% | yes, or the target is a refusal |

About 92% of supervised tokens reward content the buffer does not supply.
[prepare_evidence_data.py:606](../scripts/prepare_evidence_data.py#L606) states the intent:
"unusable evidence must not COST anything". That protects language quality and teaches the
opposite of offloading. Conversation weighting flips the gradient share toward QA (the two audits
put it at 60% and 77% by different splits; read the builder's own print), and roughly half of that
QA weight is refusal phrases from a closed set of 15, which stop carrying signal within a few
hundred steps.

Context-parametric inversion (2410.10796, ICLR 2025) is the named risk: when the finetuning
context agrees with what the weights hold, reliance on context rises early and then falls while
benchmarks keep improving. This corpus is that recipe. A gap that passes at 10M tokens can decay,
so the reliance metric has to be read at every checkpoint.

### 4.2 No counterfactual data, no conflict test (confirmed)

Every gold chunk agrees with the world. Nothing can tell "reads the evidence" from "evidence
agrees with the weights". Faithfulness-QA (2604.25313) is the portable recipe: swap the answer
entity in the gold chunk for a same-type entity, label follows the chunk. SQuAD is already a
source.

### 4.3 Reader bandwidth (unverified as a limit, confirmed as a description)

One cross-attention, read once per loop, three loops, summed with the shared experts under one
`post_norm`. The 24 dense layers never see evidence. CEPE (2402.16617) and KBLaM (2410.10450) read
at every layer on a frozen decoder; the per-layer detail is from the paper bodies, not the
abstracts. The +3.23 nat ceiling was measured in-context, through every layer. Pandey et al.
(2603.11513) measured models of 7B and under ignoring oracle passages 85 to 100% of the time on
questions they could not answer alone. Whether the port closes a useful share of the ceiling is
exactly what the first run measures, so G3 should be reported as a fraction of 3.23, not against
0.3 nats, which is 9% of it.

### 4.4 The real run recipe leaves most facts in the loss (confirmed)

NEXT.md 7e attaches a same-document span to 30 to 50% of documents, uses a real index only on
QA and Wikipedia slices, and masks fact spans only there. The other half of the corpus keeps full
loss on every fact. The store is 21M KILT passages against a 100B-token training corpus, so most
corpus facts are not in the store and can only be memorized. Knowledgeless LMs (2607.12831) and
Co-LMLM (2607.07707) both impose the suppression in pretraining, across the corpus.

### 4.5 The budget was never recomputed with evidence (partial)

Evidence costs ~118 MFLOP per evidence token against ~502 per prompt token, so throughput scales
by `1 / (1 + 0.235 r)` with `r` the evidence-to-prompt ratio. That multiplier is this review's
derivation.

| r | cost multiplier | tokens in 1k h at 97k tok/s base |
|---|---|---|
| 0 | 1.00 | 349B |
| 0.45 (web) | 1.11 | 314B |
| 1 | 1.24 | 281B |
| 2 | 1.47 | 238B |
| 3.75 (current corpus) | 1.88 | 186B |

The run closes at 1k hours for any ratio. At 5k hours it is data-bound (100B tokens x 4 epochs),
which trips the plan's own unpark condition for the diffusion trunk. Singh et al. (2604.00715)
found 91% of the retrieval gain at one store token per model parameter, which puts a useful store
for this model near 0.4B tokens.

### 4.6 Nothing measures the goal (confirmed)

R1 to R5 are prose in NEXT.md:1618. `eval_benchmarks.py` cannot attach evidence, so G5 and G6
cannot be read. The closed-book floor is already met by the seed (TriviaQA 0.014, NQ-open 0.002),
so it says nothing until the conflict and edit tests exist. G3b's 0.65 is 2.2 sigma over the 0.584
probe against the repo's own 3 sigma rule; the bar is 0.674. The groundedness head's AUROC is not
scored by the eval script.

Acceptance criteria that would make the goal falsifiable:

| id | metric | bar | home |
|---|---|---|---|
| A1 | closed-book EM, pathway off, neutral prompt, by obscurity tier | tail tiers near chance, no more than 2x the seed | `eval_benchmarks.py` |
| A2 | fixed-target answer CE, gold minus none, held-out rows | at least 50% of the in-context ceiling; distractor minus none at most 0 | `eval_abstention.py --evidence-port` |
| A3 | counterfactual follow rate, stratified by entity frequency | follows the chunk at least 90%, answers from memory at most 5% | new condition |
| A4 | store edit: change or delete the chunk and its near neighbours | at least 70% of edits propagate | two-store swap |
| A5 | selector mass on the gold chunk in `mixed`, per loop | AUROC at least 0.674 | `eval_abstention.py` |
| A6 | reasoning over evidence: HotpotQA, BoolQ and SciQ through the port against in-prompt | port matches in-prompt | `eval_benchmarks.py` |

A6 matters more than it looks. BoolQ, with the passage in the prompt, reads 0.46 / 0.44 / 0.42
against a chance of 0.50, and GSM8K is 0.009. Part of that is a yes/no policy bias. It is still
the only reading of "reasons over supplied text" the repo has, and it is not positive.

## 5. Recommended order

1. Reword the goal (section 2) in NEXT.md and add A1, A3, A4 as gates. Drop the parametric memory
   row unless the goal reverses.
2. Apply section 3 items 1 to 4. No GPU needed.
3. Run the `--evidence` finetune to 10M tokens as a mechanism check, with a position-free reader
   as a second arm. Report the fraction of the ceiling closed. A pass says the port reads. It says
   nothing about where facts live.
4. Build A2, A3 and A5 into `eval_abstention.py`, and an evidence path into `eval_benchmarks.py`.
5. Add a builder mode for the pilot corpus: fact spans masked or entities anonymized on every
   evidence-attached document, the store built from the training corpus with the document itself
   excluded, counterfactual rows, bge hard negatives, HotpotQA rows with one hop withheld. Log the
   share of supervised tokens whose facts are in the buffer as a build metric.
6. From-scratch pilot on the 5090, 100 to 150M parameters, 1 to 2B tokens, retrieval from token 0,
   with a matched-token control without retrieval. This is the first experiment that can falsify
   the goal. Fold it into the existing 7c pilots, none of which attaches retrieval today.
7. Only if step 3 closes under half the ceiling: a reader per loop, or reads in several dense
   layers.
8. After the pilot: InfoNCE and rank distillation on the query adapter (2603.08429), reader
   attention distilled into the selector where no gold label exists (2012.04584), the append-only
   buffer with a staged two-hop eval.

Deferred until an A-gate has a pilot reading: the LM head rank work, FP8, the preference pass.

## 7. The loop: internal reasoning over what is read

Second pass, same day: three audits (loop forward, objective, recorded measurements), three
literature sweeps, three competing designs, one Opus 5.5 verdict. The design page is
[evidence_path_design.html](evidence_path_design.html).

### 7.1 What the architecture already guarantees

The selector and the reader both query the state a loop starts with
([moe.py:602](../modules/model/moe.py#L602)), and chunks are encoded independently of each other.
A chunk that can only be found through a fact in another chunk is unreachable until that fact is
in the state. So k hops over evidence need at least k loops, and `n_loops: 3` caps composition at
about 2 to 3 hops before readout. The architecture forces depth; the data never asks for it.

### 7.2 What the objective does to depth

| mechanism | today | effect | status |
|---|---|---|---|
| per-loop CE | 0.2 / 0.3 / 1.0, one shared norm and head | every loop state must be token shaped | confirmed; at full depth loop 1 gets about 5% of loop 3's per-token pull |
| random depth | 30% of steps stop at loop 1 or 2 with weight 1.0 | intermediate readout share goes from 33% to 52% | arithmetic confirmed |
| `loop_scale` | 0.637 / 0.326 / 0.098 after `post_norm`, outside `is_fresh_loop_param` | loop 3 adds at most about a tenth of a unit update | confirmed |
| `evidence_loop_scale` | applied before `post_norm` | reweights the read inside the normalized sum, cannot lift the ceiling; the comment at moe.py:636 overstates it | confirmed |
| shared block gradient | about 65% / 29% / 7% through loop 1 / 2 / 3 | trained mostly as a first pass | approximation |
| selection loss | one gold vector for every loop, shares renormalized | two gold chunks push every loop to 0.5 / 0.5 | confirmed |
| readout | nothing between the last loop and the head | the loop-3 read is decoded unprocessed | confirmed |
| progress | no term on state change | loop 1 can satisfy the final loss through the residual | confirmed |
| depth past 3 | CE 3.4112, 3.4115, 3.4213, 3.4384, 3.4618, 3.4900 for loops 3 to 8 | overthinking, on plain text without evidence | confirmed |
| extra inference loops | scales clamp to the last entry, `loop_enc` does not | loops 4+ see unseen sinusoid rows | confirmed |

`loop_ce_weights: [0, 0, 1]` runs, but it is a trap while `loop_count_sampling` is on:
`loop_ce_weights_for` returns the zeros unrescaled ([pretrain.py:343](../scripts/pretrain.py#L343)),
so 30% of steps carry no CE, and the head still runs on loops 1 and 2 at weight 0.

No measured loop number is free of the halt gate. The gate passed 8% of the loop-3 update for all
16B pretraining tokens, and every later arm grafted onto that lineage.

### 7.3 Proposed design (from-scratch pilot)

```
L = CE(head(coda(h_D))) + 0.1 MTP(coda(h_D)) + 0.01 aux + 0.1 L_sel + 0.1 contrastive + 0.1 grounded
p[k,c] = selector mass of loop k on chunk c, renormalized over visible chunks
u[c]   = 1 - prod over loops k in the gradient window of (1 - p[k,c])
L_sel  = mean over (selector, token) of mean over visible c of BCE(u[c], gold[c])
```

- Depth D drawn from {3: 0.6, 4: 0.2, 5: 0.1, 6: 0.1}. The first D - 3 loops run under `no_grad`
  and are detached; the last three carry gradient. Minimum 3, so loops 1 and 2 are never exits.
- `loop_inject` on, because a detached prefix otherwise leaves the decoder without main-CE
  gradient on those steps. `loop_scale` and `evidence_loop_scale` length 6, fresh `1/sqrt(6)`.
  `loop_enc` clamped to the trained depth at inference.
- A 2-layer coda after the loop, its own KV slots, zero-init residual branch. MTP reads the coda.
  Convergence exit stays off.
- Data shares by tokens: 55% web text with retrieval, 15% evidence QA, 10% synthetic chains,
  20% chat replay. Chains use fictional entities, hops 1 / 2 / 3 at 25 / 50 / 25, 6 to 14
  distractors including a decoy chain, shuffled order; 4-hop and unseen hop-2 templates held out.
- Validity rule for the chains: accuracy with fewer loops than hops must sit at chance. Anything
  above it is a data leak.

Rejected by the verdict: a no-regress hinge between loops (puts token loss back on intermediate
states), staged evidence per loop (7.1 already enforces it, and staging leaks hop order), per-hop
selection targets (latent hops do not align to loops), an explicit reader-to-query feedback path
(query drift was measured without evidence), a coda grafted onto the current checkpoint.

### 7.4 Ladder on the 5090

| rung | tokens | runs | read | pass |
|---|---|---|---|---|
| R0 | 0 | `eval_stage0` with `loop_scale` x 1, 2, 3.5, 5.9 | CE gain loop 2 to 3 | 0.02 nats, loops 1 and 2 not worse |
| R1 | 10M | the planned `--evidence` run | selector AUROC per loop | loop 2 or 3 beats loop 1 by 0.02 |
| R1b | 0 | one micro step at depth 3 and depth 6 | peak memory | fits |

| R4 | 4 x 1B | from scratch 120M, loss placement x coda | held-out-template 2-hop at 3 loops | +10 points over per-loop without coda |

R4 replaces the 7c test in NEXT.md:1334, which changes loss placement, depth sampling and the coda
in one arm. A null at R3 decides nothing, given the graft record.

### 7.5 How strong the case is

Strong: 7.1, and small looped models composing on synthetic tasks (Saunshi et al., Schwarzschild
and Bansal, CODI and Deng et al. at 124M, TRM at 7M). Weak: transfer to natural multi-hop at this
size (second hops fail off template, Zhang et al.; BoolQ here reads below chance). Absent: any
unconfounded loop measurement in this repo, and any published looped model with an evidence port
showing a depth curve on real questions.
